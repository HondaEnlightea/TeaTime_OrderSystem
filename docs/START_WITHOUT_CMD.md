# 起動ファイルを使わない運用

`.cmd` は起動コマンドをまとめた補助ファイルです。TeaTime本体はNode.jsで動作するため、`.cmd`を開かずに利用できます。追加の有料サービス・アカウント・パッケージは不要です。

**他の方のPCをLAN親機にするための手順は、[LAN_START_GUIDE.html](../LAN_START_GUIDE.html) にまとめています。** ブラウザで開き、Node.jsの導入からコピー用コマンド、LAN起動、別端末の接続まで進められます。HTML自体は手順書で、自動的にインストール・起動するプログラムではありません。プロジェクト一式をその方のPCへ渡せば、作成者のPCを使用せずに運用できます。

## 独立会計を使うPC

1. [Node.js公式サイト](https://nodejs.org/en/download)から **24.14以降の24系**を導入します。既に導入済みなら再インストールは不要です。
2. 受け取ったプロジェクトをZIPから展開し、書き込み可能な場所に置きます。新規導入では他人の `data/` と `backups/` をコピーしません。`server.mjs`、`public/`、`lib/`、`config/`が必要です。
3. エクスプローラーで `server.mjs` が見えるフォルダーを開き、一覧の空白部分を右クリックして **「ターミナルで開く」** を選びます。PowerShell・コマンドプロンプトのどちらでも同じコマンドを使えます。管理者として開く必要はありません。
4. 次を入力し、`v24.14.0`以降の24系であることを確認します。

   ```text
   node --version
   ```

5. 会計専用として起動します。

   ```text
   node server.mjs --cashier
   ```

6. ブラウザで `http://127.0.0.1:3000/cashier` を開きます。ポートを変更している場合は起動案内のURLを使います。
7. ターミナルは営業中ずっと開いておきます。ブラウザを閉じても保存済みの記録は残ります。終了するときはターミナルでCtrl+Cを押します。

`npm start`、`.cmd`、PowerShellスクリプト（`.ps1`）は使いません。PowerShellの実行ポリシーを変更する操作も不要です。「ターミナルで開く」が表示されない場合の方法は [HTMLの手順3](../LAN_START_GUIDE.html#launch-title) にあります。

## キッチン・LANも直接起動できる

以下は用途別の選択肢です。同じPC・同じポートで複数を同時起動しません。

| 用途 | ターミナルに入力 | ブラウザで開く画面 |
| --- | --- | --- |
| 独立・会計 | `node server.mjs --cashier` | `http://127.0.0.1:3000/cashier` |
| 独立・キッチン | `node server.mjs --kitchen` | `http://127.0.0.1:3000/kitchen` |
| LAN親機 | `node server.mjs --lan` | 起動案内の `/portal`、会計・キッチン・番号表示 |

独立キッチンでは `http://127.0.0.1:3000/display?setup=1` を外部ディスプレイ用に開きます。独立会計と独立キッチンはそれぞれのPCで起動し、番号入りの紙の注文票を渡します。

LAN運用は、Node.jsを動かせるキッチンPCだけで起動します。別の会計PC・スマートフォンは同じネットワークにつなぎ、起動案内の **`http://親機のIPv4:3000/portal`** をブラウザで開きます。別端末へソースコードを配布したりNode.jsを導入したりする必要はありません。相互通信できるテザリングなどで、実際の機器を使って確認してください。

## 開かないとき

| 表示・状況 | 対応 |
| --- | --- |
| `node` が見つからない | Node.jsを導入したか確認し、ターミナルを閉じて開き直す |
| `server.mjs` が見つからない | エクスプローラーで実際にそのファイルがあるフォルダーを開き、そこからターミナルを開く |
| Node.js 24を使うよう表示される | `node --version`を確認し、24.14以降の24系を使う |
| ポートが使用中 | 起動済みTeaTimeを確認し、同じサーバーを二重に起動しない |
| 会計端末で親機URLが開かない | 親機のLAN起動と、同じネットワーク・正しいIPを確認する。[通信確認手順](WIFI_CHECK.md)を参照 |
| Node.js自体が管理ポリシーでブロックされる | 利用を許可された親機PCでLAN運用し、会計側はブラウザだけを使う。独立運用が必要なら、そのPCでNode.jsの利用許可が必要 |

今回の共有先で表示された警告は未確認なので、ブロックの原因は断定していません。Windowsには不明なアプリを制限する仕組みがあります（[Microsoftの説明](https://support.microsoft.com/en-us/windows/security/threat-malware-protection/smart-app-control-frequently-asked-questions)）。この手順はセキュリティ機能を無効化する操作を含みません。Node.jsを直接実行しても管理ポリシーに阻まれる場合、必ず動くとは保証できません。
