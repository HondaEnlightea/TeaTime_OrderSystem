## PIN廃止・数字の視認性改善（v3）

- ユーザー指定により、全モードのPIN認証・ログイン画面・ログアウト・音声開始時のPIN入力を撤去。旧DBにPIN設定が残っていても使用しません。
- `start-local.cmd` を専用検証DB/ポートで実際に起動し、「PIN・ログインは不要」の案内と、ログインなしで会計画面が開くことを確認しました。
- 自動テスト27件成功。旧PIN設定のあるDBを含む全3モードで、認証Cookieなしの読み書きを確認。Origin/Host/入力/送信サイズ検証・限定ファイル配信は維持しています。
- PC 1280px：完成番号をArial優先の太いゴシック系、weight 800、約105pxへ拡大。準備中はweight 700、約38px。等幅・ライニング数字を指定。007/072/181/609/888/9999で枠内に収まり、横の欠けがないことを確認。
- 390px：PINなしで会計画面を開き、紅茶400円＋ミルク50円の会計確認まで操作。内容幅375px・スクロール幅375pxで横はみ出しなし。

## ローカル起動の分離修正（v4）

旧start-local.cmdは「同一PCの会計・キッチン共有」を起動しており、独立した2台PCという要件に合っていませんでした。start-local.cmd / npm start は用途選択式へ変更しました。1は独立会計、2は独立キッチンです。指定なしで共有モードには入らず、自動共有はLAN起動で明示します。

- 自動テスト31件成功。Nodeの実プロセスを起動して、指定なし→会計選択、--local→キッチン選択、--lan→共有という起動経路を検証しています。
- 独立会計からキッチン・番号画面を開いた場合は会計へ、独立キッチンから会計画面を開いた場合はキッチンへ誘導します。キッチンの番号表示は利用できます。
- start-local.cmdを2つの専用検証DB/ポートで実際に起動し、1と2を選択。会計側がcashier、キッチン側がkitchenであることを確認しました。物理的に2台のPCを設置した現地検証ではありません。
- 会計側で紅茶＋氷450円、受付001を登録。キッチン側には自動追加されないことを確認した後、紙の番号として001と注文内容を手入力し、準備中へ追加できることを確認しました。
- PC表示と390px幅で手入力欄を確認。390pxの内容幅・スクロール幅は375pxで横はみ出しなし。これはブラウザの幅検証で、スマホ単独の独立運用を意味しません。
- 手入力はキッチンPCの /kitchen で行い、外部ディスプレイは /display を別ウィンドウで開きます。
- 旧共有用data/teatime.sqliteは削除しません。独立会計/キッチンには別のDBを使用し、自動コピー・合流はしません。
