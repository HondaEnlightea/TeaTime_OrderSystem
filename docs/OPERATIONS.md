# 当日の運用・復旧

2026-10-14、ユーザーから学校Wi-Fiで端末間通信が遮断されたとの報告、その後テザリングが確認できたとの報告を受けています。テザリングでTeaTimeの通信確認・注文共有が通れば連携運用を使い、2台PCの独立運用を予備とします。開発担当による学校・テザリング環境の現地実測ではありません。

## 開店前に運用方式を決める

別のPCへ新規導入する場合は [READMEの導入手順](../README.md) を参照し、ソース一式とNode.js 24.14以降の24系を用意します。既存の `data/`・`backups/` は新規配布に含めません。営業を引き継ぐ移行では、先に全会計端末の同期と予備番号の利用終了を済ませ、復旧JSON・CSV・DBバックアップを保存し、旧親機を正常停止してから記録を移します。ブラウザの未同期記録はフォルダーのコピーだけでは移りません。旧親機と新親機を同時に使わず、移行後に新しい接続先で通信・注文・音声を確認します。

`.cmd` がブロックされた場合は、エクスプローラーで `server.mjs` が見えるフォルダーを開き、一覧の空白部分を右クリックして「ターミナルで開く」を選びます。独立会計は `node server.mjs --cashier`、独立キッチンは `node server.mjs --kitchen`、LAN親機は `node server.mjs --lan` で直接起動できます。PowerShell・コマンドプロンプトのどちらでも同じコマンドを使え、`.cmd`・`.ps1`・npmは不要です。[起動ファイルを使わない運用](START_WITHOUT_CMD.md) に配布先向けの手順があります。Node.js自体が使えない会計端末は、利用できる親機のLANへブラウザで接続します。独立運用にはその端末でNode.jsを動かす必要があります。

他の方のPCを親機にする場合は、プロジェクト一式と一緒に [LAN_START_GUIDE.html](../LAN_START_GUIDE.html) を渡してください。そのPCのブラウザで手順書を開き、Node.jsを導入して `node .\server.mjs --lan` を実行します。作成者のPCは不要で、保存先とIPは新しい親機のものになります。HTMLは自動実行ランチャーではなく、コピー用コマンドを含む手順書です。

`start-local.cmd` を使用する場合は、会計PCで **1（会計専用）**、キッチンPCで **2（キッチン専用）**を選びます。キッチンPCでは `/kitchen` の手入力画面と、外部ディスプレイ用 `/display` を別ウィンドウで開きます。`/display` 自体はお客様向けの表示画面です。

**独立運用**は、会計PCとキッチンPCが通信せずに動きます。両PCにNode.js 24.14以降の24系とこのフォルダーを用意し、会計PCでは `start-cashier.cmd`、キッチンPCでは `start-kitchen.cmd` を開きます。各端末で `http://127.0.0.1:3000` を開き、ログインなしでそのまま操作します。紙の注文票を会計からキッチンに渡す担当・経路を決めてください。

**連携運用**は、キッチンPCだけで `start-lan.cmd` を開きます。起動案内は「このPCで開くリンク」「別の端末で開くリンク（接続先候補）」それぞれに、会計・キッチン・番号表示の3リンクを表示します。キッチンPC自身は `http://127.0.0.1:3000/kitchen`、同じPCの番号表示・音声準備は `http://127.0.0.1:3000/display?setup=1` を使います。会計スマートフォン/PCは別端末向けの `http://キッチンPCのIPv4:3000/cashier` を開きます。同じサーバーに接続して同じ注文を操作します。会計端末で独立サーバーを起動しません。

**3台に分ける場合**は、各端末で「端末用入口」（`http://親機のIPv4:3000/portal`）を開き、「接続できました」を確認してから会計・キッチン・番号表示の担当画面を選びます。移動先は確認できたIP・ポートを引き継ぎます。読み上げは表示用PCだけで開始し、そこにスピーカーを接続します。親機の電源を落とさず、スリープさせず、起動ウィンドウを閉じないでください。

2026-10-18に注文・売上・提供履歴・予備番号割当と旧バックアップを再度初期化しました。今回はメニューの編集内容を保持しています。更新版サーバーを起動し、以前使用した各端末・ブラウザのスタッフ画面を元の接続先で一度再読み込みしてください。端末内の旧下書き・紙番号入力・未同期記録はこの再読み込みで一度だけ消し、その後の注文は保持します。音量・声の設定は残します。確認までは `data/test-reset.json` を保持します。別端末の保存領域は、その端末が接続するまで消去できません。配布済みの別PCのDBも、このPCでの削除だけでは消えません。

連携モードのトップ `/` にも会計・キッチン・番号表示の3つの入口があります。番号表示は新しいタブで開くため、元の画面を残してディスプレイへ移動できます。キッチン画面上部の番号表示リンクも同様に使えます。

会計スマホから接続できるか、開店前に確認します。学校Wi-Fiが使えなくても、テザリング・専用LANで通信を確認できれば連携できます。連携を確認できなければ、別位置の2台PCによる独立運用を選びます。スマートフォンだけで独立会計を実行することはできません。

## 開店前の準備

1. PCを電源につなぎ、スリープ・自動ロックを営業中は避けます。起動ウィンドウを閉じないでください。
2. 画面がPIN入力なしで開くことを確認します。独立運用ではPCごとに別DBです。
3. 会計画面の「メニュー変更」タブで、提供メニュー28品（300/400/500/600円）、販売中/売り切れを確認します。メニュー説明に説明・おすすめオプションを記入し、メニュー変更でアレルギー情報も設定します。未編集の仮メニューは起動時に移行します。編集済みで仮名が残る場合は「提供メニューを読み込む → 内容確認 → 変更を保存」で切り替えてください。
4. 氷・ミルク各50円/杯を注文票にも明記します。氷・ミルク両方なら100円/杯追加です。
5. 練習を終えて営業回を切り替えます。LANでは先に各会計端末の「管理 → 営業設定 → この端末を同期・利用終了」を行います。未同期がゼロ、親機に残る割り当てがゼロ、未提供がゼロで切り替えられます。独立運用では両PCで営業回名を揃え、会計の開始番号を001に設定します。新しい営業回で番号が再利用されるため、古い控えを混ぜません。
6. キッチンPCに外部ディスプレイを「拡張」で接続します。スタッフ用キッチン画面と番号表示を別ウィンドウで開き、番号表示だけを外部ディスプレイへ移動します。
7. `/display?setup=1` または番号画面下部の「音量」で準備します。Googleの日本語音声があれば優先されます。ない場合はGoogle音声のあるChrome、または表示されている日本語音声を選んでください。
8. BGMを当日使う音量で再生し、「チャイム＋声を試す」を押します。チャイムと読み上げを別々に調節し、チャイムが十分聞こえ、声がBGMに埋もれないことを会場で確認します。BGM自身は再生アプリで調節します。
9. 「音声呼び出しを開始」を押します。別ブラウザでもPINは不要です。開始時にチャイム・声は出ません。F11で全画面表示にできます。
10. 注文→番号記入→キッチン受付→完成→呼出→お渡しまで練習し、会計側でバックアップを保存します。
11. LANの会計画面を直近の注文履歴より下までスクロールし、「切断中に使える番号」が50件以上あることを確認します。必要なら同じ欄の「予備番号を追加」を押します。「再同期」「端末記録を保存」もここにあります。接続中は残り10件未満で自動追加します。番号は各端末へまとめて割り当てるため、欠番や端末ごとの飛びは正常です。紙の注文票を渡す担当・経路も用意します（ユーザー確認済み）。

Google音声はOS・Chrome・通信環境によって利用できない場合があります。インターネットなしの独立運用でも注文・番号管理・チャイムは動きますが、Google音声をオフラインで利用できることは保証しません。端末内の日本語音声か口頭呼出を予備にします。

## 会計係

1. 茶種タブは「紅茶」「緑茶など」です。ウーロン茶と緑茶は「緑茶など」から選びます。必要なら茶葉名で検索します。
2. 茶葉を1回押すと1杯が別の行へ追加されます。同じ茶葉を2杯なら2回押し、それぞれの「氷」「ミルク」でその1杯のあり/なしを選びます。選択を変えても他の行は変わらず、同じオプションでも行はまとめません。「この1杯を削除」で取り除けます。スマホ幅では画面下の「注文・オプションへ」から注文欄へ移動できます。会計確認も1杯ずつ表示し、登録時に同じ茶葉・オプションをまとめてキッチンと集計へ送ります。
3. お預かり金額を直接入力するか、金額欄の下にあるテンキーで入力します。「クリア」は金額だけを空欄にし、⌫は末尾1桁を削除します。「ちょうどのお支払い」も使えます。数字は末尾へ追加されるので、金額を入れ直すときは先にテンキーのクリアを押します。合計とお釣りを確認します。上限1,000,000円を超えるテンキー入力は反映しません。
4. 「会計を確認」→実際に代金を受け取って「受領・注文登録」。オンライン決済は行いません。
5. 受付番号を注文票・お客様控えに記入します。独立運用とLAN切断中は注文票をキッチンに渡します。茶葉、数量、氷・ミルクの有無も記入してください。LANの「端末に保存しました」は親機への共有完了を意味しません。「親機への保存が完了しました」で同期を確認できます。
6. 「次の注文へ」を押します。独立会計の履歴は「会計登録済み」であり、キッチンの完成・提供状態は自動反映されません。

## 会計の管理タブ

- **注文履歴**：営業回を選び、番号・茶葉・備考で検索します。「取消・返金」のみの表示も可能です。カードから明細・履歴・返金操作を開きます。
- **売り上げ**：売上額・販売杯数・会計件数を確認します。「茶葉別CSV」は茶葉ごとの杯数と売上、「杯数別CSV」は1注文の杯数ごとの件数・売上です。どちらも取消・返金を除外します。
- **メニュー変更**：新規追加、茶葉名、茶種、価格、販売中/売り切れ、アレルギー情報（500文字以内）を編集し、「変更を保存」を押します。売り切れを解除するときは販売中へ戻して保存します。変更前の注文・売上は変わりません。
- **メニュー説明**：おすすめオプションとアレルギー情報を茶葉の説明とともに確認できます。おすすめの空欄は「未設定」、アレルギーの未入力は「未確認」です。原材料や追加オプションについて確認した内容は「メニュー変更」で記入してください。「説明を編集」で味・香り（2000文字以内）とおすすめ（100文字以内）を記入し、「説明を保存」を押します。おすすめは会計画面には表示・自動選択しません。未保存の変更があるままページを離れるとブラウザが確認します。同時編集で競合したら、入力内容を控えてから最新のメニューを読み直してください。

個人情報を除いて提供された表は `config/menu.json` に保存済みです。お茶28品とミルク・アイス各50円を区別し、品目の表記・価格・茶種・おすすめを保持します。JSONの編集だけでは編集済みDBを自動で置き換えません。「提供メニューを読み込む」は28品を編集中の画面へ読み込み、「変更を保存」するまでDBを変更しません。同名が1件だけの既存商品からは説明・アレルギー情報・販売状況を引き継ぎます。売り切れや説明の変更は保存後に反映され、独立会計と独立キッチンの間で自動同期しません。更新版の反映は営業開始前にサーバーを正常停止・再起動してから会計画面を再読み込みします。

2026-10-16の調査に基づく説明・アレルゲン情報を `config/menu-notes.json` に用意しています。再起動時に、同じID・名前の空欄だけへ一度補完します。手入力がある欄は保持し、以後の明示的な消去も保持します。「提供メニューを読み込む」でも、既存の空欄には調査メモを使います。調査内容と出典・商品照合上の留意点は [メニュー説明・調査一覧](MENU_DESCRIPTIONS.md) を参照してください。

アレルゲンは実物照合前の情報です。アーモンド・りんご・オレンジを記載した品目は対応する公式情報に基づきますが、同名別商品・販売国・配合改定の違いまで一致を保証しません。メーカー不明のスイートミルクティー、同名候補のモロッカンミント等は「未確認」です。実物の原材料・アレルギー表示、追加ミルク、調製時の交差接触を確認してからスタッフ向け情報を確定してください。牛乳・乳製品を追加する場合は乳成分を含みます。

## キッチン・提供係

1. 独立運用では紙の**会計発行番号**を「注文票の受付番号」へ入力し、「準備中に追加」を押します。注文内容は紙を参照し、必要なら内容欄にも入力します。キッチンで新しい番号を採番しません。登録済み番号は拒否されます。
2. 連携運用では会計で登録された注文が自動表示されます。番号と茶葉・数量・氷/ミルクを確認します。会計の通信切断中は、届いた紙の番号を同じ手入力欄から登録します。既に一覧にある番号を新規登録せず、その注文を使ってください。復帰後の会計同期は同じ番号に合流し、提供状態を保ちます。
3. 注文のお茶がすべて完成したら「完成・呼び出し」を押します。部分完成の呼出は行いません。
4. 番号が右の提供可能欄へ移り、チャイム→350msの間→「受け付け番号〇〇のお客様」と読み上げます。自動呼出はこのタイミングだけです。
5. お客様の控えと番号を照合してお渡しし、「お渡し完了」を押します。番号は表示から消え、履歴に残ります。
6. 聞き逃し・再生失敗のときだけ「再呼出」を明示的に押します。音声担当は番号表示の1ウィンドウだけです。

## 取消・返金

会計の「注文履歴 → 詳細・返金 → 取消・返金」から、現金を返金したうえで理由を記録します。売上から除外され、記録は残ります。連携運用ではキッチンからも未提供注文を取り消せますが、返金を会計係に引き継いでください。

独立運用では**会計側の取消とキッチン側の番号取消を、それぞれ記録**します。キッチンの番号取消だけでは会計の売上は変わりません。両係に連絡し、紙の注文票にも取消・返金を記入します。

切断中の自端末の未同期会計は、履歴から返金を記録し、現金返金とキッチンへの連絡を行います。復帰後にキッチンが先に提供済みにしていた場合も、この返金記録を売上・監査履歴へ反映します。通常の同期済み提供済み注文・過去営業回の訂正は対象外です。紙に訂正を記録して集計時に調整します。取消番号は再利用しません。

## 学校Wi-Fiの確認

一人でもPCとスマホの2台があれば確認できます。詳しくは [Wi-Fi確認手順](WIFI_CHECK.md) を参照してください。LAN起動時に表示される「端末用入口」（`/portal`）を別端末で開くと、注文を作らず接続を確認し、会計・キッチン・番号表示へ移動できます。旧 `/connection-check` は廃止し、転送せず404を返します。PC1台でlocalhostが開くことだけでは端末間通信は確認できません。

- 会計端末とキッチンPCを同じ学校Wi-Fiへ接続し、キッチンPCで `start-lan.cmd` を起動します。
- 会計スマホの `localhost` はキッチンPCを指しません。表示されたキッチンPCのIPv4接続先を使います。
- 複数IPはPCの複数のネットワーク接続を示す候補です。起動案内に表示された接続名を確認し、会計端末と同じネットワークのIPv4を選びます。テザリングならテザリング側の候補を使用します。
- 接続できない場合、学校の方針に沿ったNode.jsの受信許可、端末間通信禁止・クライアント隔離を学校の担当者に確認します。
- 設定を変更できない場合は、開店前に2台PCの独立運用を選びます。アプリで学校のネットワーク制限を解除することはできません。
- 親機のIPが変わった場合は新しい接続先を使います。未確認の登録がある場合は、元の注文が保存されているか先に照合します。

## 登録結果が不明・通信切断

独立会計はWi-Fi不要です。登録結果が不明な注文は内容を固定したまま、同じ端末・ブラウザ・URLで「登録結果の確認・再送」を押します。新しい注文として入力し直しません。独立キッチンの紙番号も元の識別子で再送できます。

LANの会計は、開店前に割り当てた予備番号を使い、端末への保存が完了してから受付番号を表示します。保存に失敗した場合、または番号の残りがゼロなら受付を止めます。切断中も会計・番号発行・履歴・売上・杯数・CSV・未同期注文の返金記録を使えます。画面右上の赤い「! 通信切断」はスクロールしても残ります。キッチンのスタッフ画面にも警告を出しますが、お客様の番号表示には出しません。

1. 会計画面を開いたまま操作し、番号・茶葉・数量・氷/ミルクを紙の注文票に記入してキッチンへ渡します。
2. キッチンPCは127.0.0.1の画面で紙の番号を入力し、準備・完成・お渡しを続けます。キッチンの手入力は売上に含みません。
3. 会計の履歴・売上・メニュー説明は上部タブで移動します。ページを再読み込み・閉じず、サイトデータを消さず、プライベート閲覧を使いません。ブラウザを閉じても未同期の保存記録は残りますが、切断中の画面再起動は保証しません。
4. 売上には自端末の未同期を含みます。他端末の売上・メニュー・売り切れは最後に接続した時点の情報です。メニュー変更を係同士で伝え、保存操作は接続復旧後に行います。明細CSVの「同期状況」で未同期を確認できます。集計CSVも自端末の未同期を含むので、閉店の最終集計は同期完了後に出し直します。
5. 接続が戻ると自動同期します。紙で先に登録した同じ番号へ会計が合流し、完成・提供済み・音声履歴を保ちます。再送でも二重計上しません。黄色い未同期表示が消え、未同期0件になることを確認します。
6. 「同期を確認」や要確認件数が残る場合は「再同期」で確認し、「端末記録を保存」でJSONを控えます。記録を消したり、別注文として打ち直したりしません。親機の営業回・DB・番号の重複を紙と照合します。

### 切断箇所ごとの継続範囲

| 切断・停止 | キッチンPC（127.0.0.1で操作） | 会計端末 |
| --- | --- | --- |
| 外へのインターネット接続だけが切れる | 注文管理・番号表示を継続 | PCへのローカル通信が残っていれば共有も継続 |
| 会計端末とPCのWi-Fi/テザリング接続が切れる | 到着済み注文と紙番号の完成・提供を継続 | 開いた画面・準備済み番号で会計を継続、紙を渡し復帰後に同期 |
| キッチンPCのサーバー停止・スリープ・電源断 | サーバー復旧が必要。番号表示は最終状態のまま | 開いた画面・準備済み番号の範囲で端末保存。キッチンには紙で連絡 |
| 会計画面を閉じる・再読み込みする | 親機が動いていれば継続 | 画面再表示は接続復旧後。同じブラウザ・URLで保存記録を同期 |

Google音声の再生可否は注文管理とは別です。インターネットが切れた場合は当日の声で確認し、端末内音声や口頭呼出を予備にします。

### IP・端末が変わる場合

端末記録は接続先（ホスト・ポート）とブラウザごとに保存されます。キッチンPCのIPが変わると、同じスマホでも別の保存先になります。

1. 元の会計画面を閉じる前に「端末記録を保存」でJSONを保存します。元の端末で新しい注文を受けるのを止めます。
2. 新しい接続先を開き、「管理 → 営業設定 → 端末記録の復旧（JSON）」で保存したファイルを選びます。同じ親機の記録だけを受け付けます。
3. 保存済みの注文も元の識別子で照合するため、二重登録しません。未同期0件を確認します。復旧ファイルの未使用番号は新規会計に使いません。
4. 復旧した旧端末の割り当ても「この端末を同期・利用終了」で閉じます。会計を再開するときは「注文・会計」で新しい予備番号を準備します。

元の画面に入れずJSONもない場合は、元の接続先を復旧するか、紙の注文票と親機の履歴を照合してから対応します。ブラウザのサイトデータや営業DBを削除して解決しません。

## 開店後に独立運用へ切り替える場合

LANのまま切断中の会計・キッチン手入力を継続する運用を優先します。独立DB間には自動合流がありません。どうしても方式を変える場合は受付を一時停止し、未同期ゼロと全端末の割り当て終了を確認して、CSV・DB・紙を保管します。

独立会計の開始番号は、実際に受け付けた最後の番号ではなく、親機が予備番号を含めて割り当て済みの範囲より後にします。範囲を照合できなければ、未提供を解消して両係で新しい営業回と控えの識別を決めます。キッチンで既存の連携DBを引き継ぐ必要がある場合だけ、停止後にTEATIME_DBをそのDBへ指定してキッチン専用で起動します。旧連携分の売上と新しい独立会計の売上は別々に保存・集計し、重複入力しません。この切替を現地で未練習のまま行わないでください。

## 音声が出ない

1. Windowsの音量、出力先、スピーカー接続を確認します。BGMが鳴っていてもブラウザの音量が別に下がっていないか確認します。
2. 番号表示の「音量」でチャイム・声の設定と声の候補を確認し、テストします。
3. Google音声が使えないときは端末内の日本語音声を選びます。日本語音声がない場合はOSに用意するか、口頭呼出を行います。
4. 「音声呼び出しを開始」を押します。更新・再起動後は自動開始しません。
5. 他のウィンドウが音声担当なら、そのウィンドウを閉じ、15秒待って開始します。
6. 呼び損ねた番号だけキッチンから再呼出します。再生完了通知が出ても実際のスピーカーで聞こえたかを確認します。

音量0でも呼出の再生済み記録は進みます。戻した後に必要な番号は明示的に再呼出してください。停止中は新しい呼出を取得せず、再開すると未処理で提供可能な番号を呼びます。現在再生中の呼出は最後まで流れます。

## 閉店・保管・復旧

- LANでは各会計端末の未同期がゼロになるまで同期し、「管理 → 営業設定 → この端末を同期・利用終了」を実行します。親機に残る割り当てもゼロにします。別タブが開いていても終了状態を保存します。同じ営業回で再開する場合は「予備番号を追加」を押します。
- 未同期が残った端末のJSONを保存します。親機DBのバックアップだけでは、まだ親機へ届いていない会計は保護されません。全端末の同期後に最終CSVを出します。
- 独立運用では会計・キッチンをそれぞれ照合します。売上は会計側、提供履歴はキッチン側で確認します。
- 売上は登録済み・取消以外の会計合計。独立キッチンの番号管理は含めません。料金は税込扱いです。
- 会計CSVは明細ごとに1行です。集計するのは**商品小計**。注文合計を全行で足すと重複します。取消行は除外してください。
- 集計は売り上げタブの「茶葉別CSV」「杯数別CSV」で保存できます。集計CSVの金額と販売杯数はそのまま合計でき、取消は既に除外されています。
- CSV・DBバックアップを保存し、各PCでCtrl+Cを押して正常停止します。PC故障に備え、バックアップをUSB等にも保管します。
- 独立運用は `cashier.sqlite` / `kitchen.sqlite`、連携は `teatime.sqlite`。バックアップは `backups/各モード/` の最新288件です。

復元は、対象PCを停止し、現在のDBと `-wal` / `-shm` を別フォルダーへ退避してから、整合したバックアップを該当DB名で配置します。古いWAL/SHMを新しいDBへ混ぜません。`TEATIME_DB` を使う場合はその指定先へ復元します。旧版のPIN設定が入ったバックアップも、現在はPINなしで利用できます。

復元後は採番位置も過去へ戻ります。発行済み控えと照合し、未提供を解消して新しい営業回を作り、開始番号を発行済み番号の次へ設定します。独立キッチンでも現在の営業回の番号重複を避けます。失われた会計は紙と照合して重複しない分だけ記録し、音声を開始し直してください。
