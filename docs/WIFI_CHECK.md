# 一人で行う学校Wi-Fiの通信確認

2026-10-14、ユーザーから学校Wi-Fiで端末間通信が遮断されたとの報告、その後テザリングが確認できたとの報告を受けています。テザリングでTeaTimeの通信確認・注文共有が通れば連携運用を使い、2台PCの独立運用を予備とします。開発担当による学校・テザリング環境の現地実測ではありません。

必要なのは **キッチン用PCと会計用スマートフォンの2台**です。一人で両方を操作して確認できます。PC1台のlocalhost確認では、別端末との通信可否は分かりません。

## 注文を作らず接続を試す

1. 実際に使うPCとスマホを学校のWi-Fiに接続し、必要な学校側のログインを済ませます。試験中はスマホのモバイルデータを切り、学校Wi-Fiで試していることを確かめます。
2. キッチンPCで `start-lan.cmd` を起動します。既に起動しているTeaTimeが同じポートを使っている場合は、その起動ウィンドウで正常停止してから切り替えます。会計側で別サーバーを起動しません。
3. PC自身で `http://127.0.0.1:3000/portal` が開くことを確認します。PORTを変更している場合は、その番号を使います。
4. 起動ウィンドウの「別の端末で開くリンク」にある **「端末用入口」** のURLをスマホのブラウザへ入力します。例：`http://192.168.1.23:3000/portal`。この例のIPをそのまま使わず、学校Wi-FiのPCのIPv4を使います。複数のIPが出た場合は起動案内の接続名とWindowsのネットワークの詳細を見て、スマホと同じネットワークのIPv4を確認します。テザリングで試す場合はその接続先候補を使います。
5. スマホに **「接続できました」** と確認時刻が出れば、そのPC・スマホ間でTeaTimeへのHTTP通信ができています。「接続を再確認」を押し、時刻が更新されることを確かめます。このページは注文・売上を変更しません。
6. 会計とキッチンの予定位置に機器を置き、数分後にも確認します。その後、練習専用DBで注文登録→PCキッチンへの反映→完成→提供済みを練習します。

端末用入口から「注文・会計へ」「キッチン・お渡しへ」「番号表示・音声準備へ」で担当画面へ進めます。同じ接続先を使用するため、IPを入力し直す必要はありません。番号表示を3台目のPCに分ける場合、そのPCでも同じ確認を行い、番号表示へ進んで音声を開始します。別端末はブラウザだけで使い、サーバーは親機1台だけで起動します。

独立運用の `start-local.cmd` / `start-cashier.cmd` / `start-kitchen.cmd` は他端末へ公開しないため、この通信試験には **LAN起動**を使います。スマホのlocalhost/127.0.0.1はPCを指しません。

## 開けない場合の切り分け

- PC自身でも開けない：TeaTimeの起動・ポート・入力したURLを確認します。
- PCでは開くがスマホでは開けない：学校Wi-FiのIPv4、同じ学校ネットワークに接続していること、学校ログインや端末の接続状態を確認します。
- URLが正しくても、PCの受信通信の制限や学校Wi-Fiの端末間隔離が原因になる場合があります。同じWi-Fi名でも相互通信できるとは限りません。端末間隔離の一般的な仕様は [Ciscoの説明](https://documentation.meraki.com/Wireless/Operate_and_Maintain/How_Tos/Firewall_and_Traffic_Shaping/Wireless_Client_Isolation) にあります。これは学校の機器がCisco製だと判断したものではありません。
- Windowsの受信許可が必要なら、学校の方針に従って担当者へNode.js/TCP 3000の利用を相談してください。ファイアウォール全体を無効化する方法は使いません。許可の意味は [Microsoftの説明](https://support.microsoft.com/en-us/windows/security/firewall/risks-of-allowing-apps-through-windows-firewall) を参照してください。

開けなかったという結果だけで、学校Wi-Fiが禁止していると断定はできません。上記の原因を切り分け、許可や設定が不明なままなら、2台PCの独立運用と紙の注文票で実施します。

確認が成功しても当日の混雑・電波・接続時間制限・IP変更まで保証はできません。確認日時、Wi-Fi名、機器、会場位置、結果を控え、開店前にもう一度試してください。今回の開発環境では学校Wi-Fiの実測はしていません。

## 学校Wi-Fiが利用できない場合の別構成

2台PCの独立運用を予備として用意します。会計PCは start-cashier.cmd、キッチンPCは start-kitchen.cmd を使い、紙の注文票に会計発行番号・茶葉・杯数・氷/ミルクを記入します。キッチンでは紙の番号を手入力し、完成・呼出・提供済みを管理します。売上・CSVは会計PCで集計します。番号管理はキッチンで二重の売上を計上しません。

自動共有を使う場合の候補は、学校に利用可能なネットワークを用意してもらうこと、許可された持込ルーターで専用LANを作ること、2台PCを専用の有線LANで接続することです。専用LANは学校回線への接続を必要とせず、端末間通信が可能な機器・設定を選び、インターネット未接続での起動と接続維持を事前に試します。Google音声のインターネット要否は別に実機確認します。

どの専用LANでも共有する場合はキッチンPCだけで start-lan.cmd を起動し、会計端末はそのPCのIPv4へ接続します。独立運用の2つのDBを自動共有・自動合流する構成ではありません。ネットワークを変えた後は `/portal` と練習注文で確認します。

テザリングも試験候補ですが、利用端末や接続方式によって端末間通信・接続維持の条件が異なります。Windowsのモバイルホットスポットは既存のインターネット接続を共有する機能です：[Microsoftの案内](https://support.microsoft.com/en-us/windows/experience/connectivity-networking/use-your-windows-device-as-a-mobile-hotspot)。iPhoneのインターネット共有はモバイルデータを使います：[Appleの案内](https://support.apple.com/en-au/111785)。TeaTimeの端末間通信が動くことは実機で確認する必要があります。今回いずれの代替ネットワークも実測していません。
