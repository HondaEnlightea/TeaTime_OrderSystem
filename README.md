# ティータイム同好会オーダーシステム

学祭の喫茶店で、注文・会計・受付番号の発行から、お茶の完成呼び出し・受け渡しまでを管理するWebアプリです。金銭の受け渡しはスタッフが行います。オンライン決済はありません。

**通信不要の独立運用**と、**親機1台で注文を共有するLAN連携運用**を選べます。最低構成は、離れた場所に置いた会計PC・キッチンPCの2台と、番号入りの紙の注文票です。

## 最初に用意するもの

- サーバーを動かすPC：**Node.js 24.14以降の24系**。独立運用なら会計・キッチンの両PC、LAN連携なら親機PCだけに必要です。
- このプロジェクトのフォルダー一式。追加パッケージのインストールやビルドは不要です。
- 操作用ブラウザ。音声を使うPCでは日本語音声とスピーカーも用意します。
- お客様向けのディスプレイ、紙の注文票・お客様控え、現金会計の道具。
- LAN連携の場合は、端末同士が通信できるテザリング・Wi-Fi・有線LAN。

[Node.js公式ダウンロード](https://nodejs.org/en/download) で**24系**を選んで導入してください。22系・25系・26系では起動できません。ターミナルで `node --version` を実行すると確認できます。動作確認環境はWindows・Node.js 24.14.1です。他OS向けの起動コマンドは後述しますが、実機検証はしていません。

## 別のPCへ渡す・導入する

1. `server.mjs`、`package.json`、`LAN_START_GUIDE.html`、`start-*.cmd`、`public/`、`lib/`、`config/`、`docs/`、`tests/`、READMEを含むフォルダー一式を、新しいPCの書き込み可能な場所へコピーします。ZIPで渡した場合は**展開してから**起動します。Gitのインストールは必須ではありません。
2. **新規に使うPCへは、既存の `data/`・`backups/` を同梱しません。** 注文・売上・メニュー編集などの記録が含まれます。存在しなければ初回起動時に必要な保存先を作成します。
3. 必要なPCにNode.jsを導入し、下記の直接起動または起動ファイルを使います。`.cmd` は必須ではありません。PIN・ログインは不要です。
4. 起動ウィンドウのURLをブラウザで開きます。ブラウザを閉じてもサーバーは動き続けます。停止は起動ウィンドウで **Ctrl+C** です。

**既存の営業を新しいPCへ移す場合**は、単なる新規導入と手順が異なります。会計端末の同期・予備番号の利用終了、CSV・復旧JSON・DBバックアップの保存を済ませ、旧PCを正常停止してから、使用モードのDBを移してください。DBだけでは会計ブラウザの未同期注文は移せません。詳しくは [当日の運用・復旧](docs/OPERATIONS.md) を参照してください。旧PCと新PCを同じ営業の親機として同時に動かしません。

## 起動方法

**他の方のPCをLAN親機にする場合は、[LAN_START_GUIDE.html](LAN_START_GUIDE.html) をブラウザで開いてください。** Node.jsの公式インストーラー、導入手順、コピー用の起動コマンド、親機・会計端末の接続方法を1ファイルにまとめています。HTMLは手順書として動き、インストールや起動は利用者が行います。作成者のPCを起動しておく必要はありません。このHTMLだけではアプリ本体の代わりにはならないため、プロジェクト一式を渡します。

### Windows：`.cmd`を使わず起動する

配布した `.cmd` がブロックされた場合も、Node.jsを直接起動できます。追加パッケージや `npm install` は不要です。

1. プロジェクト一式をZIPから展開します。エクスプローラーで **`server.mjs` が見えるフォルダー**を開き、一覧の空白部分を右クリックして **「ターミナルで開く」** を選びます。PowerShell・コマンドプロンプトのどちらでも利用できます。
2. `node --version` で **24.14以降の24系**が表示されることを確認します。
3. 独立会計は **`node server.mjs --cashier`**、独立キッチンは **`node server.mjs --kitchen`**、LAN親機は **`node server.mjs --lan`** を入力します。
4. 表示されたURLをブラウザで開きます。営業中はターミナルを開いたままにし、停止はCtrl+Cです。

この方法は `.cmd`・`.ps1`・npmを使いません。詳しい導入・エラー時の手順は **[起動ファイルを使わない運用](docs/START_WITHOUT_CMD.md)** を参照してください。共有先のPCでNode.js自体も許可されない場合は、起動可能なキッチン親機だけでLAN起動し、会計端末は `/portal` をブラウザで開く構成を使えます。共有先の制限下での実機確認は必要です。

### Windows：起動ファイルを開く

| 運用方式 | 起動するPC・ファイル | 注文の連携 |
| --- | --- | --- |
| 独立・会計 | 会計PCで `start-cashier.cmd` | 番号・茶葉・杯数・オプションを紙へ記入 |
| 独立・キッチン | 別のキッチンPCで `start-kitchen.cmd` | 紙の受付番号と内容を手入力 |
| LAN連携 | **キッチン親機PCだけ**で `start-lan.cmd` | 会計端末の注文を自動共有 |

`start-local.cmd` は「1：会計専用 / 2：キッチン専用」の選択式です。独立運用はPC内だけで動き、会計・キッチン間の自動通信はありません。

### 独立運用で開く画面

| PC | ブラウザで開くURL |
| --- | --- |
| 会計PC | `http://127.0.0.1:3000/cashier` |
| キッチンPCの操作画面 | `http://127.0.0.1:3000/kitchen` |
| キッチンPCに接続した番号表示 | `http://127.0.0.1:3000/display?setup=1` |

会計PCとキッチンPCにそれぞれサーバーが必要です。スマートフォンだけで独立会計を動かす構成は対象外です。キッチンの紙番号登録は番号管理専用で、売上を二重計上しません。

### LAN連携で開く画面

1. 親機で `start-lan.cmd` を起動します。親機自身は「このPCで開くリンク」を使います。
2. 別の端末は同じネットワークにつなぎ、起動案内の**端末用入口**（`http://親機のIPv4:3000/portal`）を開きます。
3. 「接続できました」を確認し、会計・キッチン・番号表示の3つから担当画面を選びます。別端末ではサーバーを起動しません。
4. キッチンは `/kitchen`、番号表示は `/display?setup=1` を開きます。番号表示を3台目に分ける場合も、その端末で親機のURLを開くだけです。音声は番号表示用PCだけで開始します。

起動案内には、会計・キッチン・番号表示の3リンクを、親機用と各ネットワーク候補用に表示します。複数のIPが出たら接続名を見て、会計端末と同じネットワークの候補を試します。

**`127.0.0.1` は、開いている端末自身を指します。** スマホでは親機のIPv4を使ってください。例は `http://192.168.1.23:3000/cashier` ですが、このIPをそのまま使わず、起動案内の値に置き換えます。親機のIPやポートを変えると接続先も変わります。

親機は営業中ずっと電源につなぎ、**電源を切らず・スリープさせず・起動ウィンドウを閉じず**に運用します。PINなしのLAN操作は、参加端末を管理できるネットワークで使います。インターネットへ直接公開する構成ではありません。

学校Wi-Fiでは端末間通信が遮断されたとユーザーから報告があり、その後テザリングの確認報告を受けています。当日の場所・機器で接続確認と練習注文を行ってください。[一人で行う通信確認](docs/WIFI_CHECK.md) に手順があります。

### ターミナルからの起動・練習

プロジェクトのフォルダーで実行します。次のコマンドはそれぞれの用途の代替で、同じPC・同じポートで同時に起動しません。

| 用途 | コマンド |
| --- | --- |
| 独立運用の用途を選択 | `npm start` |
| 独立会計 | `node server.mjs --cashier` |
| 独立キッチン | `node server.mjs --kitchen` |
| LAN親機 | `node server.mjs --lan` |
| 独立会計の練習 | `node server.mjs --preview --cashier` |
| 独立キッチンの練習 | `node server.mjs --preview --kitchen` |

練習は `data/preview-cashier.sqlite` / `data/preview-kitchen.sqlite` に保存し、通常のDBと分離します。`npm run preview` は会計の練習です。練習画面の `/responsive-check` では390px幅も確認できます。`--preview --lan` は使用できません。LANの練習は営業データを含めない別フォルダー一式で `start-lan.cmd` を使い、本番の接続先と混同しないようにします。

## 使い方

### 開店前

1. 運用方式と紙の注文票を渡す担当・経路を決めます。独立運用では双方の営業回と開始番号を確認します。
2. 「メニュー変更」で価格・販売状況・アレルギー情報を確認します。「メニュー説明」で案内に使う説明とおすすめを確認します。
3. 番号表示を外部ディスプレイへ移し、音量パネルで声・チャイム・読み上げ音量を調節してテストします。「音声呼び出しを開始」を押し、営業中は準備パネルを閉じて番号を見せます。
4. LANでは全端末の接続確認、会計画面下部の予備番号準備、練習用データでの注文→完成→お渡しを確認します。

### 注文・会計からお渡しまで

1. お客様の注文票を受け取り、「注文・会計」でお茶を選びます。同じお茶でも**押すたびに1杯ずつ別行**になります。
2. 各行の氷・ミルクを選びます。入力を取り消すときは「この1杯を削除」を使います。茶種タブは「紅茶」「緑茶など」です。
3. お預かり金額をテンキーまたは直接入力し、お釣りを確認します。ぴったりなら「ちょうどのお支払い」を使えます。
4. 「会計を確認」から内容を見直し、実際に代金を受領してから登録します。発行された受付番号を注文票とお客様控えへ記入します。
5. 独立運用、またはLAN切断中は、紙をキッチンへ渡します。キッチンで紙の番号と任意の内容を入力します。LAN接続中は注文が自動で届きます。
6. キッチンで「完成・呼び出し」を押すと「お渡し待ち」になり、番号画面とチャイム・読み上げが連動します。受け渡し後に「お渡し完了」を押します。

状態は **準備中 → 提供可能（お渡し待ち）→ 提供済み**です。独立会計は提供状態を管理しません。入力中の各杯は、登録時だけ同じ茶葉・オプションごとにまとめるため、キッチンや集計では数量がまとまります。

### 画面・管理機能

| 画面 | パス | 主な用途 |
| --- | --- | --- |
| 注文・会計 | `/cashier` | 1杯ずつ入力、会計、番号発行、直近の注文 |
| 注文履歴 | `/history` | 営業回・番号・茶葉・備考で検索、明細・取消・返金履歴 |
| 売り上げ | `/sales` | 売上額・販売杯数、茶葉別・注文杯数別の集計、CSV・DBバックアップ |
| メニュー変更 | `/menu` | 品目・茶種・価格・売り切れ・アレルギー情報、新規追加 |
| メニュー説明 | `/staff-menu` | 説明・おすすめの閲覧と編集、アレルギー情報の確認 |
| 営業設定 | `/settings` | 営業回・開始番号、LAN端末の同期終了・復旧JSONの読込 |
| キッチン・お渡し | `/kitchen` | 準備・完成・提供済み、紙番号の手入力・再呼出 |
| お客様向け番号表示 | `/display` | 待ち番号・完成番号、音声・音量のパネル |
| 番号表示・音声準備 | `/display?setup=1` | 番号表示を音声パネル付きで開く |
| 端末用入口 | `/portal` | 接続を確認し、会計・キッチン・番号表示を選択。注文記録は変更しない |

旧URL `/connection-check` は廃止し、404を返します。転送や新しい入口の案内は表示しません。起動案内の各ネットワーク候補に `/portal` のURLを表示します。

会計側は5つの上部タブで移動します。営業設定は「管理」にあります。独立キッチンでは売上の代わりに番号履歴を扱います。LANのトップ `/` には会計・キッチン・番号表示を同列に配置し、番号表示は新しいタブで開きます。キッチン上部の番号表示リンクも新しいタブで開きます。

売り上げタブから、**注文明細CSV・茶葉別CSV・杯数別CSV**を保存できます。選択した営業回を対象にし、集計CSVは取消・返金・キッチンの紙番号を除外します。Excel向けUTF-8 BOM付きです。注文明細CSVでは商品小計を集計してください。注文合計を明細の行数分足すと重複します。

## メニューと音声

[config/menu.json](config/menu.json) に、提供された表の30行だけを保存しています。お茶28品（紅茶23・日本茶など5）、ミルク・アイスのオプション2品です。原本CSVや個人情報を含むファイルは同梱していません。

28品の説明とアレルゲン調査は [メニュー説明・調査一覧](docs/MENU_DESCRIPTIONS.md) に、出典付きでまとめています。2026-10-16時点の茶店・メーカー公式情報を優先し、説明は2〜3文、提供表でミルク推奨の5品は「ミルクがおススメ。」で始めています。商品を特定できないものは候補・茶種の参考と明記し、アレルゲンの未確認を「なし」とは扱いません。開店前に実物の原材料表示・追加ミルクを照合してください。

説明の保存元は [config/menu-notes.json](config/menu-notes.json) です。再起動時に同じID・名前のメニューの空欄へ一度だけ補います。既存の手入力を上書きせず、補完後に画面から消した内容も次回起動で戻しません。品目・価格の表と調査メモは分離しています。

- お茶は300円20品・400円5品・500円2品・600円1品。氷（表の「アイス」）・ミルクは**各50円/杯**、両方なら100円加算です。
- おすすめオプションは**メニュー説明だけ**に表示し、会計では自動選択しません。空欄の3品は「未設定」です。
- メニュー変更は最大50品。説明は2000文字、おすすめは100文字、アレルギー情報は500文字までです。アレルギーの空欄は「未確認」であり、「なし」とは判断しません。
- 新規DBと未編集の旧仮メニューには提供メニューを反映します。編集済みのメニューは自動で置き換えません。切り替えは「メニュー変更 → 提供メニューを読み込む → 内容確認 → 変更を保存」です。同名が1件だけなら説明・アレルギー・販売状況を引き継ぎます。
- JSONだけを編集しても、編集済みDBのメニューには自動反映されません。保存後のメニュー変更も、過去の注文金額は変更しません。

音声は完成時に**チャイム → 短い間 →「受け付け番号〇〇のお客様」**と呼びます。明示的な再呼出とテストも使えます。Google日本語音声が端末のブラウザにあれば優先しますが、有無やインターネットの要否は当日のPCで確認してください。

番号表示の「音量」でチャイムと読み上げを別々に調節・保存できます。BGMは再生アプリ側で調節します。**ページの更新・PC再起動後は音声を開始し直します。** 開始ボタンを押すだけでは呼出音を鳴らしません。音量0でも再生済み記録は進むため、必要ならキッチンから再呼出してください。

## LAN通信が途中で切れた場合

最初に接続して予備番号を準備した会計画面は、**開いたままなら、割り当て済み番号の範囲で会計を続けられます。** 親機が50件ずつ重複しない番号を割り当てます。残り10件未満で追加し、画面下部の「予備番号を追加」でも追加できます。番号の飛び・欠番は正常です。

- スタッフ画面の右上に赤い「! 通信切断」を固定表示します。お客様向け番号画面には切断の文字を出さず、最後の表示を保ちます。
- 切断中も会計・番号発行・自端末の未同期注文を含む履歴・売上・杯数・CSV・未同期注文の返金記録を扱えます。他端末の情報は最終接続時点のものです。
- 番号と内容を紙でキッチンへ渡し、キッチンは紙番号を手入力します。復帰後は同じ番号へ会計を同期し、既に登録した提供状態を保持します。
- **切断中は再読み込み・ブラウザを閉じる操作を避け、上部タブで移動します。** 閉じた状態からの完全なオフライン起動は保証しません。番号の使い切りや端末保存の失敗時は登録を止めます。
- 未同期を残したままサイトデータを消したり、プライベート閲覧を使ったりしません。IPや端末を変える前に「端末記録を保存」で復旧JSONを控えます。メニュー変更の保存は復旧後に行います。

親機のサーバー停止・電源断はネットワーク切断と異なり、キッチンの操作にも親機の復旧が必要です。閉店時は全会計端末の未同期ゼロを確認し、「管理 → 営業設定 → この端末を同期・利用終了」を実行します。その後に最終CSV・バックアップを保存して正常停止してください。

## 保存先と仕組み

2026-10-18、ユーザー指定により、この作業フォルダーの注文・売上・提供履歴・予備番号割当と旧バックアップを再度削除しました。3モードとも売上・注文ゼロ、開始番号001です。今回はメニュー28品の編集内容を保持しています。以前使った各ブラウザは、更新版サーバーを起動後、**元の接続先でスタッフ画面を一度再読み込み**してください。下書き・紙番号入力・端末内の未同期記録も一度だけ消去し、その後の新しい注文は保持します。音量・声の設定は残します。配布済みの別PCのDBは、このPCでの削除だけでは消えません。

この一度だけの端末初期化には `data/test-reset.json` を使用します。全端末の確認までは保持し、新規PCへ配布する際は他の `data/` と一緒に除外します。通常の起動で営業DBを自動削除する処理はありません。

ブラウザはNode.jsのHTTPサーバーへ注文・状態を送信します。サーバーが金額と入力を検証し、受付番号・注文・明細・履歴をSQLiteへまとめて保存します。ブラウザは定期的に最新状態を取得して画面を更新します。画面を再読み込みしても、サーバーに登録済みの記録は残ります。

| 運用 | 主なDB | 自動バックアップ先 |
| --- | --- | --- |
| 独立会計 | `data/cashier.sqlite` | `backups/cashier/` |
| 独立キッチン | `data/kitchen.sqlite` | `backups/kitchen/` |
| LAN連携 | 親機の `data/teatime.sqlite` | 親機の `backups/shared/` |

独立運用は各PCに別のDBを保存し、自動で合流しません。LANは親機のDBを全端末で共有します。会計ブラウザにも予備番号と未同期記録を保存するため、**親機DBのバックアップだけでは未同期注文を保護できません。** 声・音量なども使用ブラウザ側の設定です。

- 受付番号は営業回ごとに001〜9999。使用済み・取消番号は再利用しません。
- 注文登録の再送は同じ識別子で重複を防ぎ、状態競合を検出します。音声担当は1つの番号表示画面が担当し、同じ完成イベントの重複読み上げを防ぎます。
- 注文時の名前・基本価格・氷/ミルク料金を保存し、後のメニュー編集から過去の会計を切り離します。
- お客様向けの番号表示/APIには、売上・商品明細・備考・注文操作を表示しません。
- 自動バックアップは5分ごと・営業回切替前・正常停止時。モードごとの最新288件を保ちます。DBの復元は停止中に行い、別DBの古い `-wal` / `-shm` を混ぜません。

`data/` と `backups/` はGitの対象外です。フォルダーを手作業でコピーする場合は含まれるため、配布時に除外します。使用中のDB・`-wal`・`-shm` を一時ファイルと判断して削除しません。画面の検証記録は `docs/screenshots/`、詳しい設計は [ARCHITECTURE.md](docs/ARCHITECTURE.md) にあります。

## 困ったとき・設定

| 状況 | 確認すること |
| --- | --- |
| 起動せずウィンドウが閉じる | Node.jsの導入とバージョン、ZIPを展開したか、フォルダーへ書き込めるか |
| 「ポートが使用中」 | 同じPCで起動済みのTeaTimeを確認。重複起動せず、その画面を使うか元のウィンドウで正常停止 |
| PCでは開くがスマホでは開かない | LAN起動、同じネットワーク、親機IP、端末間隔離、受信許可を [通信確認手順](docs/WIFI_CHECK.md) で確認 |
| ブラウザに接続できない | 親機の起動・スリープ・URL・ポートを確認。`index.html` を直接開かず、起動案内のHTTP URLを使う |
| 「SQLite is an experimental feature」 | Node.js 24のSQLiteに関する警告。起動URLが出て画面を使えれば、この表示だけで起動失敗ではない |
| 音が出ない | 番号表示の音声開始、声の選択、アプリとOSの音量、スピーカー出力先。他の番号画面が担当中でないか |

起動時の環境変数は `PORT`（既定3000）、`TEATIME_DB`（保存先の上書き）、`TEATIME_ALLOWED_HOSTS`（追加のホスト名）です。通常は設定不要です。同じDBを独立会計と独立キッチンで共有しないでください。詳しい停止・復旧・当日の確認は [OPERATIONS.md](docs/OPERATIONS.md) にまとめています。

## GitHub Pagesで公開できるか

**現在のシステム全体をGitHub Pagesだけへデプロイすることはできません。** GitHub PagesはHTML/CSS/JavaScriptなどの静的サイトを公開するサービスです（[GitHub公式説明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)）。このアプリの常駐Node.jsサーバー、注文API、SQLiteへの保存処理を実行する場所にはなりません。

ブラウザから通信すること自体はPagesでも可能ですが、その通信先となる別のサーバーが必要です。画面だけPagesへ置いても、現在の注文・会計・採番・共有は動作しません。画面とAPIを分けるには接続先やアクセス制限等の設計変更も必要です。

当日は本構成どおり**PC上で実行し、独立運用またはLAN連携**で使えます。GitHubはソースの保管・配布に使えます。外部ホスティングやアカウントは追加していません。

## 開発・検証記録

追加依存パッケージなし、Node.js標準HTTP/SQLiteとHTML/CSS/JavaScriptで構成しています。開発用の確認は次の2つです。

```sh
npm run check
npm test
```

自動テストは営業データを使いません。変更時の検証内容とPC・390px幅の画面記録は [VALIDATION.md](docs/VALIDATION.md) にあります。当日のGoogle音声・実際の聞こえ方・BGMとのバランス・外部ディスプレイ・ネットワークの長時間運用は、現地で確認が必要です。
