# TeaTime Order System

ティータイム同好会の学祭喫茶向け、注文・会計・受付番号表示システム。会計とキッチンを会場の別位置に置くため、**通信不要の独立運用**と、**会計スマホから注文を共有する連携運用**の両方を用意しています。

## 用意する機器と起動

Node.js **24.14以降の24系**をPCに用意し、このフォルダーを置きます。追加パッケージのインストール・ビルドは不要です。PIN・ログインは不要です。起動後に表示されたURLをブラウザで開くと、そのまま操作できます。

| 運用 | 会計側 | キッチン側 | 注文の受け渡し |
| --- | --- | --- | --- |
| **独立運用（最低構成）** | 会計PCで `start-cashier.cmd` | 別のキッチンPCで `start-kitchen.cmd` ＋外部ディスプレイ | 番号を書いた紙の注文票 |
| **連携運用** | 会計スマホまたはPCで、キッチンPCの接続先を開く | キッチンPCだけで `start-lan.cmd` ＋外部ディスプレイ | 同じ校内ネットワークで自動共有 |

独立運用では各PCのブラウザで `http://127.0.0.1:3000` を開きます。会計は `/cashier`、キッチンは `/kitchen`、外部ディスプレイは `/display?setup=1` を開いてください。**独立運用の会計端末は、Node.jsを起動できるPCが必要です。** スマートフォンだけでの独立運用は対象外です。

連携運用では、起動ウィンドウに表示される `http://キッチンPCのIPv4:3000/cashier` を会計スマホで開きます。会計側で別のサーバーを起動しません。学校Wi-Fiが端末間通信を禁止している場合は、開店前に独立運用を選びます。

`start-local.cmd` または `npm start` は、**1：会計専用 / 2：キッチン専用**を選ぶ独立運用です。会計PCで1、キッチンPCで2を選んでください。選択を省く場合は `start-cashier.cmd` / `start-kitchen.cmd`、または `npm run start:cashier` / `npm run start:kitchen` を使います。自動共有する連携運用は `start-lan.cmd` / `npm run start:lan` だけです。

## 画面

| 画面 | 接続先 | 用途 |
| --- | --- | --- |
| 注文・会計 | `/cashier` | 茶葉・数量・オプション、会計、受付番号発行 |
| キッチン・お渡し | `/kitchen` | 準備中→提供可能→提供済み。独立運用は紙の番号を入力 |
| お客様向け番号表示 | `/display` | 左22%に準備中、右78%に完成番号。太いゴシック系数字、音量パネルあり |
| 音声準備 | `/display?setup=1` | 番号画面の音量パネルを開く。声選択・テスト・開始 |
| 売上・履歴 | `/sales` | 営業回別・茶葉/オプション別集計、会計CSV、バックアップ |
| 茶葉・営業設定 | `/settings` | 茶葉名・価格・販売中、営業回と開始番号 |

会計とキッチンの操作導線を分離しています。売上・設定はヘッダーの「管理」にまとめました。

## メニューと音声

- 紅茶・ウーロン茶・緑茶を各10枠、計30枠。**正式名は未定のため仮名、初期価格は400円**です。
- 茶葉ごとに400・500・600円から設定できます。氷・ミルクは**各1杯につき50円**。両方なら100円加算。
- 同じ茶葉でも、オプションが違えば別明細です。注文時の基本価格・追加料金を保存し、後の変更で過去の売上は変わりません。
- 完成登録時だけ、チャイム→350msの間→**「受け付け番号〇〇のお客様」**と読み上げます。明示的な再呼出・テストも可能です。
- Googleの日本語音声がブラウザにあれば優先選択します。声を手動選択した場合はその選択を保存します。Google音声の有無・通信要否は当日のChromeで確認してください。
- ディスプレイの「音量」から、チャイムと読み上げを個別に調節・保存できます。BGMは再生アプリ側で調節します。
- ページの更新・PC再起動後は、音声を明示的に開始し直します。開始そのものでは音を鳴らしません。

## 保存と独立運用の境界

| 運用 | 保存ファイル | 自動バックアップ |
| --- | --- | --- |
| 独立会計 | `data/cashier.sqlite` | `backups/cashier/` |
| 独立キッチン | `data/kitchen.sqlite` | `backups/kitchen/` |
| 連携 | キッチンPCの `data/teatime.sqlite` | `backups/shared/` |

独立会計では売上・採番だけを記録し、完成・提供の状態は独立キッチンで管理します。キッチン側の手入力は**番号管理専用で、二重の売上を計上しません**。両PC間に自動同期はありません。紙の注文票で番号・茶葉・数量・オプションを引き継ぎ、取消・返金も両係に伝えてください。

受付番号は営業回ごとに001〜9999。取消番号・登録済み番号は再利用しません。再読み込み・再起動でも記録を保持します。再送は同じ登録識別子で二重登録を防ぎます。5分おき・営業回切替前・正常停止時に整合したバックアップを作成し、各モードの最新288件を保持します。

旧版の `start-local.cmd` が使用していた `data/teatime.sqlite` は、そのまま連携用の記録として残ります。独立運用は別DBのため、自動でコピー・合流しません。`TEATIME_DB` に同じファイルを指定して独立会計と独立キッチンで共有しないでください。

旧版の未変更サンプルメニューだけは30枠へ移行します。編集済みメニューと既存の注文・金額・状態・履歴は保ちます。旧注文の氷・ミルクは「未記録」として扱います。

## 設定と検証

`PORT`（既定3000）、`TEATIME_DB`（上表のDBを上書き）、`TEATIME_ALLOWED_HOSTS`（追加の校内ホスト名）を起動時に指定できます。ローカル・LANの全モードでPIN認証を使用しません。LANでは接続できる端末から操作できます。旧DBのPIN設定は利用せず、注文は保持します。ローカル/許可された校内LAN向けHTTP構成です。

```sh
npm run check
npm test
```

`npm run preview` は本番と別の `data/preview-cashier.sqlite`を使います。独立画面の練習は `node server.mjs --preview --cashier` / `--preview --kitchen`。プレビューの `/responsive-check` で390px幅を確認できます。

詳しい手順は [当日の運用・復旧](docs/OPERATIONS.md)、[設計と比較](docs/ARCHITECTURE.md)、[検証記録](docs/VALIDATION.md) を参照してください。
